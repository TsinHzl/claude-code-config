# Step 1：识别规则（提取疑问清单）

读取 `openspec/changes/{req_name}/prd/prd-parse.md`，以及 `openspec/changes/{req_name}/ui/*/ui_tree.txt`（如存在），按以下规则识别需要澄清的问题。

## 优先级分类

| 优先级 | 标记 | 触发条件 |
|--------|------|---------|
| 🔴 必须澄清 | 影响功能边界和拆分 | - 功能描述只有目标无交互流程（如"支持修改昵称"但无入口/步骤/限制）<br>- 多端/多角色行为未明确（如"用户操作"但不知是司机还是乘客）<br>- 核心流程存在分支但未说明各分支处理 |
| 🟡 建议澄清 | 影响实现细节 | - 存在未定义数值（"一定时间"、"多次"、"超过阈值"）<br>- 边界/异常情况未说明（网络失败、空状态、超限）<br>- 数据来源/接口未指定<br>- 文档中出现 TBD/待定/待确认/TODO |
| 🔵 可选澄清 | 优化类/非阻塞 | - 性能/体验要求未量化（"快速响应"、"流畅"）<br>- 埋点/统计需求提及但未定义事件<br>- 兼容性/降级策略未说明 |

## 设计稿对比识别（有 ui_tree.txt 时额外检查）

| 优先级 | 触发条件 |
|--------|---------|
| 🔴 | 设计稿中存在完整页面/流程但 PRD 未提及（可能是遗漏需求） |
| 🟡 | 设计稿中有多种状态（空态、加载、错误）但 PRD 只描述了正常态 |
| 🟡 | 设计稿 UI 层级暗示的交互与 PRD 文字描述不一致 |
| 🔵 | 设计稿中的组件命名暗示复用逻辑但 PRD 未说明 |

## 提取约束

- 每个问题必须关联到文档中的具体章节或段落
- 问题措辞明确，让用户无需翻文档就能理解在问什么
- 不提问显而易见的内容，只问文档确实缺失或模糊的
