# Flutter ↔ Native Channel 实现规范（强制）

本规则定义 `driver_uni_business` 包的 channel 接口**新增、修改、消费**完整流程。
所有 Flutter↔Native 通信由 **uniAPI 框架**生成，业务方不得手写 channel。

> `driver_uni_foundation` 工作流相同但 `oc_uniapi_prefix` / `java_package` 不同，
> 接入时参考各自 `genInterface.sh`，本规则的 IDL 与消费侧约束完全适用。

---

## 一、目录约定

```
driver_uni_business/
├── interface/                                  ← IDL 描述（手写）
│   └── {category}/{module}/
│       ├── entity/{Name}Entity.dart            ← @UniModel
│       ├── uni_native/{Name}UniNative.dart     ← @UniNativeModule (F→N)
│       └── uni_flutter/{Name}UniFlutter.dart   ← @UniFlutterModule (N→F)
├── lib/                                        ← 自动生成（禁止手改）
│   └── {category}/{module}/
│       ├── entity/{Name}Entity.dart
│       ├── uni_native/{Name}UniNative.dart
│       └── uni_flutter/{Name}UniFlutter.dart
├── android/src/main/java/.../driver_uni_business/  ← 自动生成（Java 端）
├── ios/Classes/Plugins/                            ← 自动生成（OC 端）
└── genInterface.sh                                 ← 生成器入口
```

| 路径 | 性质 | 修改权限 |
|------|------|---------|
| `interface/**/*.dart` | 手写 IDL | 业务方修改 |
| `lib/**/*UniNative.dart` `lib/**/*UniFlutter.dart` `lib/**/entity/*.dart` | 生成产物 | **禁止手改** |
| `android/src/main/java/**` `ios/Classes/Plugins/**` | 生成产物 | **禁止手改**（业务子类除外） |
| `genInterface.sh` | 生成命令 | 仅基础设施维护者修改 |

## 二、IDL 注解清单

来源包：`package:uni_api/api/api.dart`

| 注解 | 修饰对象 | 用途 |
|------|---------|------|
| `@UniNativeModule()` | `abstract class` | 声明 Flutter→Native 接口 |
| `@UniFlutterModule()` | `abstract class` | 声明 Native→Flutter 接口 |
| `@UniModel()` | `class`（普通类） | 声明跨端可序列化实体 |
| `@IgnoreError()` | 方法 | Release 模式不抛异常，仅 trackError 上报 |

**支持的参数/返回类型：**

- 基本类型：`String` / `int` / `double` / `bool`
- 容器：`List<T>` / `Map<String, V>`（V 必须是基本类型、`Map`/`List`、或 `@UniModel` 实体；Map 的 key 仅允许 `String`）
- `@UniModel()` 标注的实体类
- 异步：方法返回 `Future<T>` 即声明为异步
- 回调：参数类型 `UniCallback<T>`（事件流）

**不支持：**

- 自由 `dynamic` / `Object` 作为方法参数或返回值类型（实体必须显式 `@UniModel`）
  - 例外：`Map<String, Object>` 是项目实践中允许的"任意载荷"形态，**仅限作为 Map value**
- Dart 函数类型（`Function` / `void Function(...)`）—— 用 `UniCallback<T>` 代替
- 泛型类（仅 `UniCallback<T>` 是预置例外）

## 三、F→N 接口定义（`*UniNative`）

文件路径：`interface/{category}/{module}/uni_native/{Name}UniNative.dart`

```dart
import 'package:uni_api/api/api.dart';

/// 司机端业务 X 的 Native 调用入口
@UniNativeModule()
abstract class XxxUniNative {
  /// 同步形态（仍走 channel 异步通信，仅 API 形态同步）
  /// Map<String, Object> 是允许的"任意载荷"特例（见第二节"不支持"小节例外）
  @IgnoreError()
  String getName(Map<String, Object> map);

  /// 异步形态（返回 Future）
  Future<bool> checkXxx(String oid);

  /// 无返回值
  @IgnoreError()
  void doSomething();
}
```

**约束：**

- 类名后缀必须为 `UniNative`
- 必须为 `abstract class`
- 仅声明方法签名，**不得有方法体**
- 错误传播由 `@IgnoreError()` 控制——业务调用允许失败时加该注解

## 四、N→F 接口定义（`*UniFlutter`）

文件路径：`interface/{category}/{module}/uni_flutter/{Name}UniFlutter.dart`

```dart
import 'package:uni_api/api/api.dart';

/// Native 主动通知 Flutter 的事件接口
@UniFlutterModule()
abstract class XxxUniFlutter {
  void didLogIn();
  void willLogOut();
}
```

**约束：**

- 类名后缀必须为 `UniFlutter`
- 必须为 `abstract class`
- 方法返回值通常为 `void`（事件通知）；需要 Native 等待结果时可声明 `Future<T>`

## 五、跨端实体（`@UniModel`）

文件路径：`interface/{category}/{module}/entity/{Name}Entity.dart`

```dart
import 'package:uni_api/api/api.dart';

@UniModel()
class TestEntity {
  /// 测试字段
  List<int>? test;
}
```

**约束：**

- IDL 阶段**只声明字段，不实现 `encode`/`decode`** —— 由生成器自动注入
- 字段类型遵守第二节"支持的参数类型"
- 嵌套实体必须也是 `@UniModel`
- 字段建议全部 nullable（容错跨端版本不一致）

生成后的 `lib/` 产物会自动获得：

```dart
// Autogenerated
class TestEntity {
  List<int>? test;
  Object encode() { /* ... */ }
  static TestEntity decode(Object message) { /* ... */ }
}
```

## 六、`UniCallback<T>` 异步流式回调

适用场景：Native 处理后**多次回推**事件给 Flutter（支付状态流、扫码结果流、长连接消息等）。

### IDL 声明

```dart
@UniNativeModule()
abstract class PageUniNative {
  void openPaymentPage(Map<String, Object> map, UniCallback<String> callback);
}
```

### 业务消费

```dart
final cb = UniCallback<String>((event, disposable) {
  // 处理一次事件
  if (event == 'success') {
    disposable.dispose();   // 一次性回调用完销毁，避免泄漏
  }
});

await PageUniNative.openPaymentPage({'orderId': 'xx'}, cb);
```

### 约束（按场景区分）

#### 一次性事件回调（如支付结果、扫码结果单次返回）

- 在 `onEvent` 内拿到结果后**立即**调用 `disposable.dispose()`
- 否则 `uniCallbackCache` 持续持有引用 → 内存泄漏

#### 流式持续回调（如长连接消息、状态流）

- **不得**在首次 `onEvent` 内 `dispose`（会中断后续事件接收）
- 必须在生命周期结束时 `dispose`：Controller 持有时在 `onClose()` 内、StatefulWidget 持有时在 `dispose()` 内

#### 通用约束

- 泛型 `T` 必须是基本类型或 `@UniModel` 实体；自定义类未注解会导致 `UniCallbackManager` 无法 decode

## 七、运行代码生成器

仓库根目录已提供 `genInterface.sh`：

```bash
flutter pub run uni_api \
  --input=`pwd`/interface \
  --dart_out=`pwd`/lib \
  --java_out=`pwd`/android/src/main/java/com/didiglobal/driver/driver_uni_business \
  --java_package=com.didiglobal.driver.driver_uni_business \
  --oc_out=`pwd`/ios/Classes/Plugins \
  --dart_null_safety=true \
  --oc_uniapi_prefix=DUB
```

执行：

```bash
cd driver_uni_business
sh genInterface.sh
```

**一次执行同步产出三端代码**：

| 端 | 产物 | 业务侧后续动作 |
|----|------|--------------|
| Dart | `lib/.../uni_native/*.dart` | 直接 import 调用静态方法 |
| Dart | `lib/.../uni_flutter/*.dart` | 实现接口 + 启动期 `setup(impl)` |
| Dart | `lib/.../entity/*.dart` | 直接 import 使用 |
| Android | `android/.../*UniNative.java` | 业务编写子类 implements 抽象方法 |
| Android | `android/.../*UniFlutter.java` | 直接调用静态方法触发 Flutter |
| iOS | `ios/Classes/Plugins/DUB*UniNative.h/.m` | 业务编写实现类 conform Protocol |
| iOS | `ios/Classes/Plugins/DUB*UniFlutter.h/.m` | 直接调用 |

## 八、业务消费规范

### F→N（消费 `*UniNative`）

```dart
import 'package:driver_uni_business/biz/login/uni_native/LoginUniNative.dart';

final isLoggedIn = await LoginUniNative.isLogin();
```

### N→F（实现 `*UniFlutter`）

```dart
import 'package:driver_uni_business/biz/login/uni_flutter/LoginUniFlutter.dart';

class LoginObserverImpl implements LoginUniFlutter {
  @override
  void didLogIn() { /* ... */ }
  @override
  void willLogOut() { /* ... */ }
}

// 在启动期 LaunchTask 注册一次
LoginUniFlutter.setup(LoginObserverImpl());
```

### Import 路径约束

- 业务代码 import `*UniNative.dart` / `*UniFlutter.dart` 时**使用包内具体路径**（这些文件无 barrel export）
- 禁止 import `interface/` 目录下的 IDL 文件（IDL 仅供生成器读取）

## 九、新增 / 修改 channel 工作流

| 步骤 | 操作 | 验证 |
|------|------|------|
| 1 | 在 `interface/` 下新增/修改 `.dart` IDL 文件，加上 `@UniNativeModule` / `@UniFlutterModule` / `@UniModel` 注解 | 仅声明签名，无实现体 |
| 2 | 执行 `sh genInterface.sh` | 生成成功无报错 |
| 3 | 检查 `lib/` / `android/` / `ios/` 三端产物均已生成或更新 | `git status` 确认三端文件均出现 |
| 4 | Native 端（Android/iOS）实现 `*UniNative` 抽象方法 | 编译通过 |
| 5 | Flutter 端业务代码消费生成的类 | 类型检查通过 |
| 6 | 提交 PR：**IDL + 三端产物必须在同一 commit** | PR 文件清单包含 4 类路径 |

## 十、禁止事项

| 禁止 | 原因 | 替代 |
|------|------|------|
| 修改 `lib/.../uni_native/*.dart` `lib/.../uni_flutter/*.dart` `lib/.../entity/*.dart` 任意一行 | 下次生成会被覆盖 | 改 `interface/` 重跑生成器 |
| 业务代码内手写 `BasicMessageChannel` 调用 Native | 绕过 uniAPI，无法多端同步 | 在 `interface/` 定义新接口 |
| 直接 import `package:driver_uni_business/...../interface/...` | IDL 仅供生成器读取 | import `lib/` 路径下的产物 |
| `*UniNative` 类名缺少 `UniNative` 后缀 / `*UniFlutter` 缺少 `UniFlutter` 后缀 | 生成器按后缀识别接口方向 | 严格按规范命名 |
| 只 commit 改动的 `interface/` 不 commit `lib/` `android/` `ios/` 产物 | 其他人 pull 后构建失败 | 同 PR 提交三端产物 |
| `UniCallback<CustomClass>` 中 `CustomClass` 未加 `@UniModel` | `UniCallbackManager` 无法 decode 收到的数据 | 实体加 `@UniModel` 重新生成 |
| `UniCallback` 用完不调用 `disposable.dispose()` | `uniCallbackCache` 持续持有引用 → 内存泄漏 | 一次性回调内显式 dispose；页面级回调在 onClose dispose |
| 在生成的实体类上手动添加业务方法 | 重新生成时丢失 | 业务方法放在外部 extension 文件 |

## 十一、合规检查（codegen Layer 2）

在涉及 Native 通信的功能 codegen 后，post-codegen-check 应核对：

- [ ] 业务代码无 `BasicMessageChannel` 直接构造（除生成产物外）
- [ ] 所有 channel 调用通过 `*UniNative` 静态方法
- [ ] 所有 N→F 注册通过 `*UniFlutter.setup(impl)`
- [ ] 业务代码无对 `lib/.../uni_native/`、`lib/.../uni_flutter/`、`lib/.../entity/` 下文件的修改
- [ ] `UniCallback` 实例在合适生命周期内 `dispose`
- [ ] 跨端传输实体均带 `@UniModel`（IDL 侧）/ 生成 `encode`/`decode`（产物侧）
