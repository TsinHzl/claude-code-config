# 报告模板：code-review-single

输出 Markdown 文件严格套用以下结构：

```markdown
# 📦 仓库名称：[REPOSITORY_NAME]

**分支对比**：`[源分支]` -> `[当前分支]`

## 📝 变更概述

[简明扼要总结主要代码变动点]

## 🚨 深度审查意见

*(三大类别必须全部输出。若某类无发现，写：`本次变更未发现此类问题。`，不得省略类别标题。每类输出前统计问题总数填入标题。)*

### 🚫 严重问题 (Critical) - 共 [N] 个

**[序号]、**

* **问题描述**：[精准描述缺陷原因]
* **潜在影响**：[描述后果]
* **位置**：第 L[起始行号] - L[结束行号] 行
* **修复对比**：

  ```[language]
  // ❌ 原始代码
  [完整提取包含问题的原始代码块]

  // ✅ 修复代码
  [提供符合 Clean Code、高性能的重构代码]
  ```

* **修复重点**：[简述修复后的核心优势]

### ⚠️ 改进建议 (Standard) - 共 [N] 个

**[序号]、**

* **建议点**：[描述建议]
* **理由**：[说明为什么这样改更好]
* **位置**：第 L[起始行号] - L[结束行号] 行
* **修复对比**：

  ```[language]
  // ❌ 原始代码
  [完整提取包含问题的原始代码块]

  // ✅ 修复代码
  [提供符合 Clean Code、高性能的重构代码]
  ```

* **修复重点**：[简述修复后的核心优势]

### 💡 优雅重构 (Refactoring) - 共 [N] 个

**[序号]、**

* **位置**：第 L[起始行号] - L[结束行号] 行
* **修复对比**：

  ```[language]
  // ❌ 原始代码
  [完整提取包含问题的原始代码块]

  // ✅ 修复代码
  [提供符合 Clean Code 原则的重构代码]
  ```

* **修复重点**：[简述修复后的核心优势]

## 🏁 总结评述

* **整体评价**：[公式：10 - (严重×3) - (改进×0.5) - (重构×0.2)，最低 1 分，保留一位小数。格式：X.X 分（严重×N，改进×N，重构×N）]
* **核心风险**：[一句话总结最需要关注的改动点]
```
