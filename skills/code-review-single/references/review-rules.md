# 审查规则（统计 + 六维扫描）

## 变更统计公式

env 脚本已在源头剔除自动生成文件（`*.g.dart` / `*.freezed.dart` / `*.pb.dart` / `*.gr.dart` / `*.mocks.dart` / `*.generated.*` / lock 文件 / `Pods/` / `build/` / `.dart_tool/` 等 pathspec 排除，以及含 `Autogenerated` / `DO NOT EDIT` / `Code generated` 头注释的 file block awk 过滤）。

### 从已过滤的 diff 提取

- 涉及文件数：`diff --git` 出现次数
- 新增行数：`+`（排除 `+++` 文件头）行数之和
- 删除行数：`-`（排除 `---` 文件头）行数之和
- 净变更行数：新增 − 删除
- 涉及提交数：Step 1 commit 列表计数，无则 `N/A`
- 每文件变更类型：含 `new file mode` → 新增；`deleted file mode` → 删除；`rename` → 重命名；其余 → 修改

### 数据源约定

变更统计的输入是 Step 1 stdout 中 `=====` 分隔线之后的 diff 全文，**不要反向聚合 shard 文件**。

## 六维扫描规则

逐文件（字母序）、逐 `+` 行变更，按以下 6 项顺序扫描：

1. 安全漏洞（OWASP Top 10）
   - 硬编码凭据、API 密钥、Token
   - SQL 注入（未参数化查询）
   - XSS（未转义用户输入直接写入 DOM）
   - 缺少输入验证（系统边界处）
   - 不安全的依赖项（已知漏洞版本）
   - 路径遍历风险
   - CSRF（缺少跨站请求伪造保护的状态变更接口）
   - 身份验证绕过 / 受保护路由缺少权限检查
   - 日志泄露机密（在日志中记录 Token、密码、PII）
2. 崩溃与异常（零容忍：空指针、越界、未捕获异常、死锁、栈溢出等）
3. 逻辑错误与边界遗漏
   - 缺少错误处理（静默吞异常）
4. 性能问题
5. 代码规范与可读性
   - 函数长度 > 50 行
   - 文件长度 > 800 行
   - 嵌套深度 > 4 层
   - 调试语句残留（`console.log` / `print` / `debugPrint`）
   - 未处理的 TODO / FIXME 注释
   - 公共 API 缺少文档注释
   - 可变数据操作（应改用不可变方式）
   - 代码或注释中使用 Emoji
   - 新增代码缺少对应测试
   - 无障碍访问缺失（a11y）
   - 死代码（注释掉的代码、未使用的导入、无法触达的分支）
6. 重构机会

### 分类规则

- 🚫 严重问题：第 1、2 项一律归此类
- ⚠️ 改进建议：第 3、4、5 项发现
- 💡 优雅重构：第 6 项发现

### 输出格式

按 [report-template.md](report-template.md) 三档梯度组织：

- 🚫 严重问题：完整 5 字段（含 ❌/✅ 双代码块）
- ⚠️ 改进建议：精简 3 字段（含 ❌/✅ 双代码块）
- 💡 优雅重构：最简 2 字段（行内位置 + ❌/✅ 双代码块）
